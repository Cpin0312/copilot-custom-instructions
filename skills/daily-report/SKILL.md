# 毎日の作業報告の手順

## 使う場面
- 「今日の報告を作って」「日報」「作業報告」「明日の予定も入れて」と頼まれたとき。

## 項目（いつも同じ）
1. 日付
2. 名前
3. 作業場所
4. 今日やったこと
5. 今日学んだこと
6. 困ったこと・相談したいこと
7. 明日の予定

会社のフォームの項目がちがうときは、私が渡したフォームの項目を使い、この一覧より優先する。

## 手順
1. **集める。** その会話で私が言ったこと、渡した資料・メモから、項目ごとに当てはまるものを集める。
2. **足りない項目を1回で聞く。** 4・5・7 のどれかが空のときは、作る前に、空の項目を全部並べて1回で聞く。例：「4（今日やったこと）と7（明日の予定）を教えてください」。1・2・3 は、前の会話で分かっていればそれを使い、分からなければ一緒に聞く。6 は空でもよい（「なし」と書く）。
3. **文にする。** 私の言葉を、報告にふさわしい言い回しに整える。中身は増やさない。
   - 箇条書きで、1項目 1〜3 行。
   - 「〜した」「〜を学んだ」と言い切る。
   - 学んだことは、何を学んで、それで何ができるようになったかまで書く（私が言っていれば）。
4. **出す。** 決まった形の Markdown（下）を ```markdown のブロック1つで出す。私が「貼る用」「フォーム用」と頼んだときだけ、項目名と中身だけを記号（# や **）なしで、2つ目の ```text のブロックで出す。

## 決まった形

```markdown
# 作業報告 〈日付（曜日）〉

- **名前：** 〈〉
- **作業場所：** 〈〉

## 今日やったこと
- 〈〉

## 今日学んだこと
- 〈〉

## 困ったこと・相談したいこと
- 〈なければ「なし」〉

## 明日の予定
- 〈〉
```

## 決まり（これを破ると困る）
- 私が言っていないこと、資料にないことを「やった」「学んだ」と書かない。報告に嘘が入るのが一番困る。
- 私が「それでいい」と言って足りないまま作るときは、空の所を〈未記入〉と書く。勝手に埋めない。
- 日付と曜日が合っているかを確かめる。今日の日付が分からないときは〈日付〉と空ける。
- 名前・作業場所は、会話や資料に出てきたものだけを使う。

## 出す前の確かめ
- 7つの項目がそろっているか（6 は「なし」でよい）。
- 私が言っていないことが入っていないか。
- 貼る用も出したときは、2つのブロックの中身が同じか。
